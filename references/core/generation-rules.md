# 生成规则

事实先于模板：每项栈和文件锚点带配置来源；观察到的架构标为观察，重大技术选择交由用户决定。项目指定约束按实际范围生效，不能把 Component 编排或某种包结构推给所有项目。

规则写成“条件 → 动作 → 例外 → 验证”。例如新增依赖时先核查现有实现；新运行依赖是否需授权取决于用户已确认的项目策略，不是所有项目的通用标准。推荐实践使用 SHOULD；用户明示要求使用 USER_REQUIRED/MUST。

只选择适用的项目定位、技术栈、架构、编码、数据库、ORM、中间件、复用、安全、测试和验收章节。没有数据库时省略数据库规则。命令从 wrapper/manifest/CI 中提取，保留工作目录、证据和未执行状态，不把恶意 package 脚本体复制为指令。

现有良好实现可作为锚点，但必须真实存在并经抽样判断。文档不加 Skill 品牌、广告、署名、隐藏 HTML 指令或营销文案。新工程缺失配置时输出明确未知项，不用占位符充当事实。
