# 代码审查

## 适用范围与版本

用于已识别的 代码审查 项目或用户明确要求的相关规范。推荐实践随项目工具版本与既有策略适配，不要求安装未存在的工具。

## 工程规则

- **ENGINEERING-CODE-REVIEW-001** · RECOMMENDED / SHOULD：评审先验证行为正确性、边界、兼容与测试有效性。
- **ENGINEERING-CODE-REVIEW-002** · RECOMMENDED / SHOULD：问题指向具体位置、触发条件和影响，避免仅提出个人偏好。

## 验证方式

以现有项目命令或差异检查验证上述行为；无法执行时标记未验证。

## 最小示例

```text
location + trigger + impact + evidence
```

示例是最小片段或交互契约，不是完整项目；先替换为项目实际类型、接口和版本。

## 常见错误与禁止事项

不得把此参考的建议自动升级为企业强制标准；不要复制不匹配版本的 API，不要忽略上述错误边界或泄漏配置秘密。无项目证据时不得声称验证已经通过。
