# 工程设计

## 分层

SKILL.md 负责能力检测、自然语言模式选择、语义工作和非破坏性交付。core 参考负责决策、规则分类、来源、冲突与评分边界。技术参考按栈渐进加载。common.py 提供受限 I/O、过滤、脱敏、异常输出和原子写入；各脚本返回数据，不执行被扫描工程。

Scanner 对授权根做流式目录遍历，不一次加载巨大目录；依次执行安全排除、普通忽略、显式包含和预算。manifest 解析构建技术证据，POM 仅解析已扫描本地父级与受限属性替换，XML 拒绝实体。结构与惯例工具标记目录角色和代码模式候选，不模拟完整调用图。

生成器产生可直接审查的项目差异候选；不同栈、版本、模块和用户规则会反映到文件。智能体负责非结构化企业规则、框架版本适配和语义精简。工具不依赖 LLM API。新增技术需同时维护依赖标识、知识库与虚构测试。

## 质量契约

确定性评分固定版本，缺证据不补分，语义结论单列。规则冲突需结构化 key/value/exclusive/scope；自由文本仅候选。分数不能代表代码质量或安全认证。

## 安全交付

独占候选写入；覆盖验证原文摘要并原子替换。生成器拒绝潜在秘密或私有地址。ZIP 允许清单打包，固定元信息，包内 manifest；临时目录解压后复查所有文件摘要和 Skill 结构。运行包不含开发指令或测试恶意样本。

WorkBuddy 1.0.1发行布局采用 ZIP 根 SKILL.md 和一层资源目录；通用包保留外层技能目录与源码分层。展平映射写入 manifest.source_paths，按类别给文件加前缀，并同时改写相对链接、锚点及内联文件路径；大小写归一化后重名则拒绝发布。Python 通过 resource_path 查找源码或展平资源，不用文本替换修改代码。解压后的 CLI 回归验证中英文生成与资源完整性，防止仅目录检查通过而实际功能失效。

## 已知边界

不是完整构建工具解析器，不解析全部版本目录、所有锁文件或远程 BOM；不能从目录证明微服务/DDD。自定义 .gitignore 实现支持层级、否定、锚点、*、?、**、字符类及转义字面量，采用分段匹配与记忆化目录遍历；每条模式至多512字符、每条目录链至多2000条，超出时标记扫描不完整，并不声称完全复刻 Git 的所有边缘语义。符号链接和硬链接采取保守拒绝。摘要检查不是 OS 强制锁。无 Python 和真实宿主模型行为只能按手工验收场景验证。
